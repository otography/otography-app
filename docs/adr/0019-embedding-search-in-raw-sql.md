# 埋め込みの検索は生の SQL で書き、並べ直しも同じ SQL の中で行う

埋め込みで投稿を探す処理（`apps/api/src/embeddings/search.ts`）は、Drizzle のクエリビルダーを使わず、`sql` テンプレートで SQL をそのまま書く。この SQL は、`vector_top_k` で候補を取り、同じ SQL の中で、統計を反映したコサインで候補を並べ直す。`vector_top_k` はビルダーで書けない。また、並べ直しを Worker で行うと、Worker の CPU 時間の上限に近づく。この 2 点が理由である。

## 前提

- 保存する `z` は、変換 `z = Ax + b` で 256 次元に落としたベクトルであり、保存した後は書き換えない。統計（`z` の平均 `m` と逆共分散 `P`）が変わったときは、検索のスコアで補正する（設計ドキュメント「埋め込みの保存と中心化・白色化の設計」）。
- 補正したスコアは `⟨z_i − m, u⟩ / ‖z_i − m‖_P`（`u = P(z − m)`）である。分母は投稿ごとに異なるので、`vector_top_k` のインデックスでは計算できない。そのため、候補を取った後で並べ直す必要がある。
- `vector_top_k` は表を返す関数である。返す `id` は `post_embeddings` の rowid である。
- 手元の libSQL（`@libsql/client`）には、`vector_distance_cos` と `vector_distance_l2` はあるが、内積を求める関数は無い（2026-11-19 に確認）。
- Workers の無料プランでは、1 回のリクエストで使える CPU 時間は 10ms である。

## 理由

### 1. `vector_top_k` は Drizzle のビルダーでは書けない

- Drizzle のビルダーは、表を返す関数を `from` や `join` に置く方法を持たない。そのため、候補を取る部分は、並べ直しをどこで行っても生の SQL になる。
- 並べ直しの式をこの SQL に加えても、生の SQL を書く場所は増えない。

### 2. 並べ直しを Worker で行うと、Worker の CPU 時間を使う

- Worker で並べ直す場合、Worker は候補のベクトル（50 件で約 25KB）を受け取り、F16 を数値に戻し、内積を計算する。
- SQL の中で並べ直す場合、Worker の計算は `u = P(z − m)` の 1 回（約 6.5 万回の積和）だけになり、受け取るのは上位の投稿の id とスコアだけになる。

### 3. 並べ直しに要る値を、前もって列に持たせた

- 内積 `⟨z_i, u⟩` は、`(1 − vector_distance_cos(z_i, u)) × ‖z_i‖ × ‖u‖` で求める。`‖z_i‖` は、保存時に `post_embeddings.norm` に書く。
- 分母の `‖z_i − m‖_P` は、バッチが統計を更新するたびに計算し、`pnorm_a` か `pnorm_b` に書く。検索時に投稿ごとの行列の計算（256 × 256 回の積和）をしなくて済む。

## 検討した他の案

- **候補を SQL で取り、並べ直しを Worker で行う**：式を TypeScript で素直に書け、単体テストもしやすい。しかし、理由 2 のとおり Worker の CPU 時間と受け取るデータが増える。また、理由 1 のとおり候補を取る SQL はどちらにしても生の SQL になる。採用しない。
- **分母の `‖z_i − m‖_P` も検索時に Worker で計算する**：候補 50 件で約 330 万回の積和になり、CPU 時間の上限に近づく。採用しない。
- **内積の関数（`vector_distance_dot`）を使う**：今の libSQL には無い。Turso のドキュメントに載っているのは、Rust で書き直した新しいエンジンの関数であり、そのエンジンには `vector_top_k` のインデックスが無い。採用しない。

## この決定による影響

- 並べ直しの式が正しいことは、型検査では確かめられない。テスト（`apps/api/tests/embeddings/search.test.ts`）で、SQL の結果を TypeScript で計算した結果と比べる。
- クエリの `u` は、`vector16()` で F16 に丸めて SQL に渡す。そのため、スコアには丸めによる小さな誤差がある。
- バッチが `pnorm` を書く前の行は、`‖z_i − m‖ × √(tr(P) / k)` で分母を近似する。これらの行の順位は近似である。
- 新しいエンジンに `vector_top_k` と内積の関数の両方がそろったら、内積の部分を `vector_distance_dot` で書き直せる。
