# 回数制限は、Workers のレート制限機能で、ログイン中のユーザーごとに 3 種類に分けてかける

API の回数制限は、Cloudflare Workers のレート制限機能（バインディング）で、ログイン中のユーザーの ID ごとにかける。制限は、書き込み（`WRITE_RATE_LIMIT`）、いいね（`LIKE_RATE_LIMIT`）、読み出し（`READ_RATE_LIMIT`）の 3 種類に分ける。悪意のある大量のリクエストから、Turso の書き込み枠と、Apple Music API への問い合わせを守るためである。

## 前提

- 設計ドキュメントは、「Workers のレート制限機能で、ユーザー ID ごとに投稿・いいねの回数を制限する」「プロフィールの閲覧にも回数制限をかける」と定めている。
- Workers のレート制限機能では、上限の回数と、期間（10 秒か 60 秒）をバインディングごとに決める。回数は Cloudflare の拠点ごとに数えるので、上限は厳密ではない（Cloudflare のドキュメント「Rate Limiting」）。
- 回数制限をかける API は、すべてログインが必要である（`requireAuth`）。そのため、キーには IP アドレスではなく、ユーザーの内部 ID を使える。
- Turso の無料枠は、書き込みの行数に上限がある。投稿とお気に入りの保存は、未保存の曲やアーティストがあれば Apple Music API も呼ぶ。

## 理由

### 1. キーを IP アドレスでなくユーザーの ID にする

- 同じ IP アドレスを、複数の利用者が使うことがある（携帯電話の回線、学校や会社のネットワーク）。IP アドレスをキーにすると、無関係な利用者まで制限される。
- 回数制限をかける API はログインが必要なので、ユーザーの ID が必ずある。

### 2. 制限を 3 種類に分ける

1 つの上限ですべての API を数えると、操作の頻度の違いを表せない。いいねを続けて押しただけで投稿ができなくなる、といったことが起きる。そこで、頻度と負担が近い操作ごとに分けた。

| バインディング     | 上限          | 対象                                                   | この上限にした理由                                                                                             |
| ------------------ | ------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `WRITE_RATE_LIMIT` | 60 秒に 10 回 | 投稿、投稿の削除、プロフィールの変更、お気に入りの保存 | Turso への書き込みと Apple Music API の呼び出しを伴う。通常の利用で 1 分に 10 回を超えることは無いと考えた     |
| `LIKE_RATE_LIMIT`  | 60 秒に 30 回 | いいねを付ける・外す                                   | 一覧を見ながら続けて押すことがある。書き込みは 2 行だけで、Apple Music API は呼ばない                          |
| `READ_RATE_LIMIT`  | 60 秒に 60 回 | プロフィール、プロフィールの投稿一覧、投稿 1 件        | プロフィールの 1 回の表示で 2 回（プロフィールと投稿一覧）呼ぶ。他人のプロフィールを機械的に集める操作を抑える |

上限の値は、実際の利用を見る前の仮の値である。

### 3. 回数制限の仕組みが失敗したら、通す

- 回数制限の確認が例外になったときに 429 や 500 を返すと、回数制限の不具合で API 全体が止まる。
- 回数制限は悪用を減らすための仕組みであり、一時的に効かなくても、すぐにデータが壊れることは無い。そこで、ログに残して通す。

## 検討した他の案

- **Durable Objects や DB で回数を数える**：回数を数えるたびに、リクエストの数と DB の書き込みが増える。守りたい枠をかえって消費するので、採用しない。
- **1 種類の上限ですべての API を数える**：2. の理由により、採用しない。

## この決定による影響

- 回数制限をかけるルートでは、`requireAuth` の後に `rateLimit("…")` を付ける（`apps/api/src/lib/rate-limit/middleware.ts`）。新しいルートを足すときは、3 種類のどれに当たるかを決める。
- バインディングの namespace（1001〜1003）は、Cloudflare のアカウントの中で一意の番号である。新しいバインディングには、使っていない番号を使う。
- 画面は、429 の応答の `error` の文言をそのまま表示する。Cloudflare の 1 日の枠が尽きたとき（エラー 1027）は、応答が JSON ではない。この場合は、`apps/website/src/lib/api.ts` が「混雑しています」という文言の応答に置き換える。
