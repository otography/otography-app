# Apple Music の開発者トークンは Worker が実行時に署名し、ブラウザ用のトークンにはリクエストのオリジンを入れる

Apple Music API の開発者トークンは、署名済みのトークンをシークレットとして登録する形にはせず、Worker が実行時に秘密鍵で署名する。署名したトークンは、有効期間を 12 時間にして、モジュールスコープにキャッシュする。ブラウザ（MusicKit JS）に渡すトークンには、リクエストのオリジンを `origin` クレームとして入れる。署名済みのトークンは有効期間が最長 6 か月なので、シークレットとして登録する形では、期限が切れる前に作り直して登録し直す作業が続くからである。

## 前提

- 開発者トークンは、ES256 で署名した JWT である。`exp` は、発行時刻から 15777000 秒（6 か月）より後にはできない（Apple の「Generating Developer Tokens」）。
- 開発者トークンを使うのは、次の 2 つである。
  - ブラウザの MusicKit JS：曲の検索と試聴に使う。
  - Worker：まだ保存していない曲を Apple Music から取得するときに使う。
- Apple は、Web のクライアントに渡すトークンには `origin` クレームを入れることを推奨している。`origin` を入れたトークンは、リクエストの `Origin` ヘッダーが `origin` の値のどれかに一致するときだけ使える。
- Preview の URL は Preview ごとに異なる（ADR 0008）。

## 理由

### 1. 署名済みのトークンをシークレットとして登録すると、作り直す作業が続く

- 署名済みのトークンの有効期間は、最長でも 6 か月である。そのため、シークレットとして登録する形では、6 か月以内ごとにトークンを作り直し、本番と Preview に登録し直す必要がある。登録し忘れると、トークンの期限が切れた時点で、曲の検索も取得もできなくなる。
- 実行時に署名する形では、秘密鍵を 1 回登録すれば、トークンを作り直す作業はない。

### 2. ブラウザ用のトークンは、オリジンを限定し、有効期間を短くする

- ブラウザに渡したトークンは、利用者が取り出して、他のサイトや他のプログラムで使うことができる。`origin` クレームを入れると、他のオリジンのページからは使えなくなる。
- `origin` の値には、固定の URL ではなく、`/api/music/token` へのリクエストの URL のオリジンを入れる。Preview の URL は Preview ごとに異なるので、固定の URL では Preview で使えないからである。workers.dev のホスト名へのリクエストは、そのホスト名を持つ Worker にだけ届くので、リクエストの URL のオリジンは、本番、Preview、ローカルのどれかになる。
- 有効期間を 12 時間にするのは、トークンが漏れたときに使える期間を短くするためである。

### 3. 署名の処理時間は短い

- 2026-11-17 に Node.js で計測したところ、署名は 1 回あたり約 0.6 ミリ秒だった。ただし、最初の 1 回は、秘密鍵の読み込みを含めて約 23 ミリ秒かかった。
- 署名したトークンは、isolate ごと、オリジンごとにキャッシュする。期限まで 1 時間を切ったトークンだけを作り直すので、署名は isolate ごと・オリジンごとに、およそ 11 時間に 1 回である。

## 実装

- `apps/api/src/apple-music/token.ts`
  - `getDeveloperToken({ origin })`：`origin` が `null` なら Worker 用、文字列ならブラウザ用のトークンを返す。キャッシュのキーは `origin` である。
  - 秘密鍵は、最初に使うときに 1 回だけ読み込む。
- `apps/api/src/index.ts`：`GET /api/music/token`（ログインが必要）は、リクエストの URL のオリジンを `origin` にしたトークンを返す。応答はキャッシュさせない（`Cache-Control: private, no-store`）。
- シークレット：`APPLE_TEAM_ID`、`APPLE_KEY_ID`、`APPLE_MUSIC_PRIVATE_KEY`（Media Services を有効にした鍵の `.p8` の中身）。

## 検討した他の案

- **署名済みのトークン（有効期間 6 か月）をシークレットとして登録する**：理由 1 のとおり、作り直して登録し直す作業が続くので、採用しない。Workers で署名の CPU 時間が 10 ミリ秒の上限に収まらなかった場合は、この案に切り替える。
- **ブラウザ用のトークンにも `origin` を入れない**：理由 2 のとおり、取り出したトークンを他のサイトで使えるので、採用しない。

## この決定による影響

- Workers での署名の CPU 時間は、まだ計測していない。特に、秘密鍵を読み込む最初の 1 回が、CPU 時間の上限（10 ミリ秒）に収まるかを、Workers Logs で確かめる必要がある。
- ページを 12 時間より長く開いたままにすると、ブラウザが持つトークンの期限が切れる。その場合の扱いは、曲を検索する画面を作るときに決める。
